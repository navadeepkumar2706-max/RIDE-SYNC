## 5. HERO FEATURE — FIND PASSENGERS ALONG MY ROUTE

This is the most important new RideSync feature.

Create a feature called:

"ON MY WAY — Smart Passenger Discovery"

### Driver Workflow

1. Driver opens Offer a Ride.
2. Driver selects starting location.
3. Driver selects destination.
4. Driver selects departure date and time.
5. Driver enters available seats.
6. Driver clicks "Find Passengers Along My Route".
7. The system calculates the driving route.
8. The system searches MongoDB for passenger ride requests compatible with that route.
9. Matching passenger requests appear on the map.
10. Driver can review each request and invite the passenger.

### Passenger Workflow

1. Passenger opens Find Rides.
2. Passenger enters pickup and destination.
3. Passenger selects date and time.
4. Passenger searches for available rides.
5. Passenger sees matching drivers.
6. Passenger can request a seat.

If no matching driver exists, allow the passenger to create a ride request.

Store these passenger requests in MongoDB.

### Matching Algorithm

Use a practical, explainable matching algorithm.

Inputs:
- Driver pickup coordinates
- Driver destination coordinates
- Driver route geometry
- Passenger pickup coordinates
- Passenger destination coordinates
- Requested departure time
- Requested seats

Initial filters:
- Same travel date
- Compatible departure time, default ±30 minutes
- Enough available seats
- Active ride/request status

Route matching:
- Determine whether passenger pickup is close to the driver's route.
- Determine whether passenger drop-off is close to the driver's route.
- Ensure pickup occurs before drop-off along the route.
- Calculate approximate pickup and drop-off detours.

For the MVP:
- Default route corridor: 2 km
- Maximum estimated detour: 10 minutes when routing data is available
- Time flexibility: ±30 minutes

Make these thresholds configurable.

Use geographic calculations to shortlist candidates before requesting expensive detour routes.

Use an established geospatial library such as Turf.js if needed.

Do not treat nearby pickup alone as a valid match.

A passenger must have both a compatible pickup and drop-off location in the correct travel direction.

### Match Score

Calculate an explainable compatibility score based on:
- Route compatibility
- Departure time difference
- Detour duration
- Seat availability

Display:
- Match percentage
- Pickup location
- Drop-off location
- Departure time
- Estimated detour
- Seats requested

If detour estimates are unavailable, clearly label the result as an approximate route match rather than displaying invented values.

### Map Visualization

Show:
- Driver route as a cyan line
- Driver starting point as a green marker
- Destination as a red marker
- Compatible passenger pickup points as blue markers
- Passenger drop-off points with distinct markers

Clicking a passenger marker opens a card showing:
- Passenger display name
- Pickup area
- Drop-off area
- Time compatibility
- Requested seats
- Match score
- Invite Passenger button

Only show requests that the passenger has made discoverable.

Do not expose exact home addresses or phone numbers before an appropriate booking/consent step.
